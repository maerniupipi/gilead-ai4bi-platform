# 后端项目说明（backend）

> **文档维护强约束：每次修改代码（新增/调整目录、接口、响应格式、DTO 字段）必须同步更新本文档和根目录 `变更日志.md`。**
> 本文档是 AI / 新成员的"首要参考"，准确性直接影响开发质量。

## 2. 关键文件职责

### `main.py`
- 统一响应包装：**ResponseEnvelopeMiddleware** 仅对 `Content-Type: application/json` 的成功响应做信封包装；**流式接口**（如 `text/event-stream`）保持原样透传
- 全局异常处理：HTTPException → `{code, message, data: null}`，code 来自 `core/response.py`
- 路由注册入口：`knowledge_router`、`auth_router`、`model_provider_router`、`chat_router`、`autobi_router`、`xlsx_qa_router`；新增大类时在此追加 `app.include_router(...)`

### `core/database.py`
数据库基础设施：`engine` / `SessionLocal` / `Base` / `get_db`。  
所有域的 repository/router 统一从此处导入 `get_db`，ORM 模型从此继承 `Base`。

### `core/redis_client.py`
- 环境变量：`REDIS_HOST`（空则实验室追踪不落 Redis、用进程内内存）、`REDIS_PORT`、`REDIS_USERNAME`、`REDIS_PASSWORD`、`AUTOB_LAB_TRACE_TTL_SECONDS`
- **本机回环**（`127.0.0.1` / `localhost` / `::1`）且未设 `REDIS_USE_AUTH_ON_LOCAL=1` 时，强制不传用户名与密码，便于无 ACL 的本地 Redis

### `services/chat/service.py`
- `send_chat` / `stream_chat`：原有聊天接口
- `stream_chat_text_deltas`：解析 OpenAI 流式 `delta.content`，产出纯文本增量（供 AutoBI 网关第 17 步总结流式输出）

### `core/response.py`
响应码枚举 `ResponseCode`：

| 码 | 含义 |
|----|------|
| `SUCCESS` | 成功 |
| `NOT_FOUND` | 资源不存在 |
| `BAD_REQUEST` | 请求参数有误 |
| `DUPLICATE` | 唯一性冲突（如名称重复） |
| `VALIDATION_ERROR` | 请求体/路径参数校验失败 |
| `UNAUTHORIZED` | 未登录/Token 无效 |
| `FORBIDDEN` | 无权限 |
| `SERVER_ERROR` | 服务器内部错误 |

### `models/` 包
- 每个文件对应一组实体（按 ORM 关系层级分组）；`__init__.py` 统一导出所有类，外层代码 `from app import models` 后仍可直接用 `models.KnowledgeBase`
- 新增表：在对应 `models/*.py` 添加类，再补 `init_tables.sql`
- **跨文件 relationship 用字符串引用**（如 `relationship("KnowledgeAccess")`），SQLAlchemy 懒解析，无循环导入风险

### `schemas/` 包
- 每个文件对应一个 domain（对齐 router）；`__init__.py` 统一导出所有 DTO，外层代码 `from app import schemas` 后仍可用 `schemas.KnowledgeBase`
- 新增/修改 DTO：在对应 `schemas/<domain>.py` 修改，并同步前端字段

## 3. 分层职责与禁止事项

### router.py（controller 层）
✅ 只做：接收参数（path/query/body）→ 调 service → 返回结果  
🚫 禁止：直接写 `db.query(...)` / `joinedload` / 业务逻辑

### service.py（业务层）
✅ 只做：业务规则校验、编排多个 repo、管理事务（`db.commit()` / `db.refresh()` 在此）  
🚫 禁止：直接组装复杂 ORM 查询（下沉到 repository）

### repository.py（数据访问层）
✅ 只做：所有 `db.query / db.add / db.delete / joinedload` 细节  
🚫 禁止：抛 `HTTPException`、执行 `db.commit()`

## 4. 统一响应格式

**成功：**
```json
{ "code": "SUCCESS", "message": "success", "data": <业务返回值> }
```

**失败：**
```json
{ "code": "NOT_FOUND", "message": "Knowledge base not found", "data": null }
```

由 `main.py` 中间件和异常处理器自动处理，**router 无需手动包装**。

## 5. 大类 / 域 / 子模块层次规则

```
routers/
  <category>/          ← 业务大类（一级，对应 main.py include_router）
    __init__.py        ← 聚合该大类下所有域的 router
    <domain>/          ← 域（二级，对应一组业务功能）
      router.py
      <submodule>/     ← 域内子模块（可选，当某域路由过多时拆分）
        router.py
```

- 新增 `knowledge` 大类下的域 → 加到 `routers/knowledge/__init__.py`，**无需改 main.py**
- 新增全新大类（如 `user`）→ 新建 `routers/user/` 并在 `main.py` 增加 `include_router`

## 7. 新增功能改动清单

### 情况 A：在已有大类下新增域

1. 创建 `routers/knowledge/<domain>/router.py` + `__init__.py`
2. 创建 `services/knowledge/<domain>/service.py` + `__init__.py`
3. 创建 `repositories/knowledge/<domain>/repository.py` + `__init__.py`
4. 在 `routers/knowledge/__init__.py` 中 include 新 router
5. 在 `models/<合适的文件>.py` 新增 ORM 模型，在 `init_tables.sql` 补建表语句
6. 在 `schemas/<domain>.py` 新增 DTO，并在 `schemas/__init__.py` 导出
7. 同步前端（`frontend/src/api/` + `frontend/src/pages/`）
8. **更新本文档 + `变更日志.md`**

### 情况 B：新增全新大类（如 `user` 权限体系）

1. 创建 `routers/user/__init__.py`（聚合路由）+ 各域子目录
2. 在 `main.py` 增加 `app.include_router(user_router)`
3. 其余同情况 A

## 8. 命名规范

- **目录名**：`snake_case`（如 `knowledge_base`）
- **文件名**：固定为 `router.py` / `service.py` / `repository.py`
- **DTO 类名**：`<Domain>Create` / `<Domain>Update` / `<Domain>` / `<Domain>Detail`
- **service 函数名**：`create_<x>_service` / `list_<x>_service` / `get_<x>_service` 等

## 9. AI/多人协作防错清单

1. router 里出现 `db.query()` → **错误**，下沉到 repository
2. repository 里出现 `raise HTTPException` → **错误**，改在 service 里抛
3. `db.commit()` 出现在 router 或 repository → **错误**，只在 service 里 commit
4. 新增接口但没有对应 DTO → **错误**，先在 `schemas/<domain>.py` 补 DTO 并更新 `__init__.py`
5. 修改了接口/DTO/响应格式但没有更新本文档和 `变更日志.md` → **错误**
