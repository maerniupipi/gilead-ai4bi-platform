# 工作流脚本任务模块清单

## 1. 适用范围

本文说明平台端工作流「脚本任务 / PYTHON3」节点的代码格式、输入输出、import 支持范围、运行限制和排错方式。

当前运行基线：

- UAT/容器：Python 3.11（见 `backend/Dockerfile`）
- 本地开发建议：Python 3.11 及以上
- 脚本编译器：RestrictedPython 8.0
- 第三方依赖来源：`backend/requirements.txt`

## 2. 脚本入口与输入输出

推荐入口：

```python
def main(input_name: str):
    return {"result": input_name}
```

规则：

| 项目 | 规则 |
|---|---|
| 入口函数 | 必须定义 `main(...)`；为兼容旧流程，也支持一个或多个 `execute_xxx(params)` |
| 参数 | `main` 参数名必须与节点「输入变量」名称一致；支持默认参数、仅限关键字参数和 `**kwargs`；缺少或多余参数会明确报错 |
| 输入来源 | 支持引用上游变量或填写常量 |
| 变量名称 | 输入名称必须是合法的 Python 参数名，不能是关键字或以下划线开头；输入/输出名称不能重复或包含点号 |
| 返回值 | 必须为 `dict`，输出必须是 JSON 可表示的文本、有限数字、布尔、对象、数组或 `None`；对象键必须是字符串 |
| 输出字段 | 已声明的每个输出变量必须存在于返回字典中，缺字段会在当前脚本节点报错 |
| 输出过滤 | 配置输出变量时仅返回声明的字段；未配置时返回全部字段，不再在字段拼错时静默透传其它结果 |
| 兼容字段 | 返回 `output` 且未返回 `result` 时，运行器原样补充 `result`，保留空字符串、`False`、`0` 和 `None` |

输入/输出变量在界面中声明为文本、数字、布尔、对象、数组等类型。常量按声明类型解析；引用上游的值和脚本返回值检查实际类型，不自动把字符串 `"2"` 当作数字。声明为数字时不接受布尔值。数组会检查每一项的类型。旧配置未声明类型时保留原值。

| 界面类型 | 常量填写示例 | `main` 实际收到 |
|---|---|---|
| `STRING` | `false` 或 `{"a":1}` | 原样保留为 `str` 文本，不解析其中的 JSON |
| `NUMBER` | `2`、`1.25` | `int` 或 `float` |
| `BOOL` | `true`、`false` | `True` 或 `False` |
| `OBJECT` | `{"a":1}` | `dict` |
| `LIST<String>` | `["问题1","问题2"]` | `list[str]` |
| `LIST<Number>` | `[1,2.5]` | 数字列表 |
| `LIST<Bool>` | `[true,false]` | 布尔列表 |
| `LIST<Object>` | `[{"a":1}]` | 字典列表 |

当前各声明类型均允许实际的 `None`（JSON `null`），脚本仍需处理空值。空数组、空对象、空字符串、`0`、`False` 均不会被替换成其它输入。无引用的旧脚本输入按“最近输出 → 流程 input → 流程 message”查找第一个非 `None` 值；新流程建议明确选择上游变量。引用不存在的字段会报错，真实存在且为 `null` 的字段仍保留为空值。

不可直接返回 `set`、`bytes`、`datetime`、`Decimal`、元组或循环对象；请分别转换为列表、文本、ISO 日期文本、数字等 JSON 值。`NaN` 和无穷大不属于有效 JSON 数字。

## 3. import 支持规则

### 3.1 支持的写法

所有绝对导入语法均支持，不再使用静态模块白名单：

```python
import json
import pandas as pd
from typing import Any, Dict, List
from urllib.parse import urlencode
from azure.storage.blob import BlobServiceClient
```

模块能否导入由实际运行环境决定：

1. Python 3.11 标准库：支持。
2. `backend/requirements.txt` 已安装的第三方包：支持。
3. 镜像中额外安装的包：支持，但不属于稳定能力承诺；重新构建镜像后可能消失。
4. 平台后端内部 `app.*` 模块：技术上可以绝对导入，但属于内部实现，不保证跨版本兼容，不建议业务脚本依赖。

不支持相对导入：

```python
from .helpers import parse_data  # 不支持
```

原因是工作流脚本是独立代码片段，不属于 Python 包。请改为绝对模块名。

未安装模块会返回：

```text
运行环境未安装模块: <模块名>；可用模块以 Python 标准库、backend/requirements.txt 和工作流脚本任务模块清单为准
```

## 4. 可用基础类型与函数

除了 RestrictedPython 默认安全内建，脚本环境已补齐常用基础能力：

```text
all, any, bool, bytearray, bytes, callable, chr, complex, dict, divmod,
enumerate, filter, float, frozenset, hash, hex, id, int, isinstance,
issubclass, len, list, map, max, memoryview, min, next, object, oct,
ord, pow, range, repr, reversed, round, set, slice, sorted, str, sum,
tuple, type, zip
```

支持字符串/数组/字典索引与切片、循环迭代、序列解包、异常抛出和捕获、函数定义及类型注解、基础类定义、变量增量赋值（如 `total += value`）。模块顶层定义的函数和导入也可以在顶层初始化或列表推导中直接使用。

`print(...)` 已可执行，文本由当前作用域的 `printed` 收集；若需要查看它，可以显式返回 `{"log": printed}` 并声明 `log` 输出字段。需要向流式运行发送进度信息时使用 `thought("处理完成")`。字符串插值建议使用 f-string；RestrictedPython 仍限制以下划线开头的属性和 `str.format` 等操作，并不等同于无约束的 Python 解释器。

## 5. 用户脚本修复后的可执行示例

```python
import json
from typing import Any, Dict, List

def main(text: str):
    try:
        data = json.loads(text)
    except json.JSONDecodeError as e:
        raise ValueError(f"无效的 JSON 格式: {e}")

    questions = data.get("questions", [])
    if not isinstance(questions, list):
        raise TypeError("'questions' 字段必须是数组")

    q1, q2, q3, q4 = (questions[:4] + [""] * 4)[:4]
    return {"q1": q1, "q2": q2, "q3": q3, "q4": q4}
```

节点配置要求：

- 输入变量：`text`，类型 `STRING`。
- 输出变量：`q1`、`q2`、`q3`、`q4`，类型均为 `STRING`。
- 示例输入：`{"questions":["问题1","问题2"]}`。
- 预期输出：`{"q1":"问题1","q2":"问题2","q3":"","q4":""}`。

## 6. 运行与安全边界

import 放宽后，脚本可以导入 `os`、`subprocess`、`socket`、数据库/对象存储客户端等高权限模块。因此必须把脚本任务视为可信后端代码，而不是面向不可信用户的安全沙箱。

当前边界：

- RestrictedPython 负责语法改写和部分内建限制，但不是进程、文件系统或网络隔离。
- 脚本在线程池中运行，当前没有独立进程级 CPU/内存/执行时长强制限制。
- 取消运行会立即停止等待脚本，不阻塞后端事件循环；已经开始执行的 Python 线程不能被强制结束，其代码和外部操作仍可能继续。需要可靠终止时必须使用进程/容器隔离。
- 脚本继承后端进程可见的环境变量、网络和文件权限；禁止在脚本中读取、记录或返回密钥。
- 脚本编辑/发布权限应只授予可信管理员或开发人员，并保留审计日志。
- 若后续开放给普通用户，必须改为独立容器/进程执行，并配置只读文件系统、网络策略、资源配额、超时和临时凭据。

## 7. 自测清单

验收标准与自动回归覆盖：

- `import json`、`typing`、未预注入的标准库（`csv`、`pathlib`）及已安装第三方包（`sqlparse`）可执行。
- 缺包和相对导入返回明确错误。
- `isinstance`、列表补齐、序列解包、循环、增量赋值、`print`、简单类定义与模块顶层辅助函数可执行。
- 文本、数字、布尔、对象和四种数组常量与声明类型一致；错误常量能定位到字段。
- 输入命名为 `input`、`metadata` 时正常；默认参数和仅限关键字参数可用；参数缺失/多余能定位到名称。
- 数值 `0`、布尔 `False`、空集合和空文本在传递中不丢失；真实 `None` 可保留。
- 返回非字典、缺少声明输出、输出类型不匹配、非 JSON 值均在脚本节点报错；额外输出按声明过滤。
- 旧 `execute_xxx(params)`、缓存及 `thought` 事件保持兼容。

运行回归（在 `backend` 目录）：

```bash
.venv/bin/python -m unittest tests.test_workflow_script_contract tests.test_agent_workflow_engine.TestScriptAndAgentConstInput -v
```

查看某个环境的实际顶层模块清单，可在对应后端容器内执行：

```bash
python -c "import pkgutil; print('\\n'.join(sorted({m.name.split('.')[0] for m in pkgutil.iter_modules()})))"
```
