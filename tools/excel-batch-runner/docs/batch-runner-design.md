# Excel 批量执行工具设计

## 本轮变更：源文件逐题回写与 SQL/回答分列
用户已明确只修改后续跑批，不恢复旧批次。页面改为输入原始 .xlsx 的本地绝对路径并点击加载，由本地服务读取；浏览器上传不能提供可回写的源路径。保留既有上传接口兼容离线测试及旧调用，但页面默认使用原路径模式。
新任务 H 写完整 SQL（多条顺序编号），I 写 text 增量拼接的最终回答；必须接收到有效 end=true 才能成功。未完成时保留部分文字并标明失败/中断；没有 SQL 或回答明确标注未返回。过程仍在详情与 JSONL 中，SQL/回答分别检查单元格容量。
在现有 Storage 锁和逐题 checkpoint 上扩展回写：开始前核对加载副本与当前源文件一致；source.xlsx 是备份，result.xlsx 是结果副本。源文件旁创建随机临时文件，完整写入并 fsync 后替换原路径。writeback.json 记录路径、已知 SHA256 和待写版本，防止中断后误判自身已写内容；任何未知外部修改停止回写。下载副本不再触发原路径写入。
新行持久化 output_format=split、sql、answer；缺少格式的历史行仍为 trace。选中行 H/I 任一已占用默认跳过，勾选覆盖表示覆盖原文件对应两列；任一目标合并则拒绝。非目标内容保持既有处理边界，复杂 Excel 对象仍需用户自行核验。
仅使用构造工作簿与内存事件验证：两列内容、独立超限、源文件逐题保存、备份、源文件变化、文件占用、取消恢复、并发串行保存与无真实连接。
以下历史设计中关于单列 H、上传副本和源文件不覆盖的内容由本节及 agents.md 新规则取代。

## 目标和范围
用户在本地页面上传 .xlsx，选择 sheet 和并发数量，配置接口并执行。每个有效 G 列问题独立请求；H 列记录整理后的完整结果，原始事件另存日志，供后续拆分。
本对话不访问接口，不读取已有项目或业务文件。开发仅使用构造数据离线验证。
本设计已获用户确认并用于实现；启动、操作及验收边界见 README.md。

## 技术方案
采用 Python + FastAPI 本地服务、httpx 流式请求、openpyxl 工作簿处理，以及原生 HTML/CSS/JavaScript。
本地服务同时提供静态页面和任务管理，前端通过同源请求获取状态，避免浏览器直接调用远端的跨域依赖。
选择该方案是为了分离 SSE 解析、任务调度和 Excel 导出，同时无需 Node 构建环境。
替代方案：Streamlit 开发页面较快，但后台任务与页面重运行协调较复杂；React 独立前端适合更复杂交互，首版会增加构建与维护成本。
依赖安装仅限项目虚拟环境；实际版本在实现阶段确定。

## 模块边界
- app/main.py：应用入口、仅绑定本机的启动配置。
- app/api.py：上传、任务启动、状态查询、停止和下载入口。
- app/models.py：配置、行状态和任务状态。
- app/workbook.py：读取 G 列、sheet 元数据、行定位和导出。
- app/sse.py：流式帧解析与原始事件。
- app/report.py：按字段整理单行报告，供执行和重启恢复共用。
- app/client.py：HTTP 请求构造、超时与响应错误处理。
- app/runner.py：共享任务队列、并发上限、状态更新和停止调度。
- app/storage.py：任务目录与原始事件持久化。
- app/static/：独立 HTML、CSS、JavaScript 文件。
- tests/：仅内存模拟与构造工作簿测试。

## 页面流程
1. 上传文件，列出 sheet、可执行行数和已有 H 内容的行数。
2. 多选或全选 sheet；起始行默认 2，可调整；G 列固定，其他列不作为请求输入。
3. 设置接口 URL、app_id、version_id、caller、channel、超时、并发数及可选请求头。
4. 展示待执行行预览；H 已有内容默认跳过，可明确选择覆盖导出副本中的已有 H 内容。
5. 点击执行后展示总进度及每行 sheet、行号、问题、状态、耗时和执行过程。
6. 按 sheet、状态及关键词筛选结果，查看详细过程；每个问题结束后立即更新任务目录的 result.xlsx，运行中可下载当前已落盘工作簿，完整日志在完成或停止后下载。
7. 停止操作停止派发新任务；已发出的请求等待完成或超时，界面明确提示这一行为。

## 请求和并发
- 初始接口配置采用用户提供的 URL、app_id=12、version_id=35、caller=agent-platform-debug、channel=api-docs。
- 输入问题同时填入 message、inputs.input、inputs.question，stream 固定 true。
- conversation_id 为每行独立生成的 UUID，结果中保留请求对应关系。
- 并发默认 3，界面可配置为 1 至 32；全体选中 sheet 共享同一个上限。
- 使用固定数量的消费者处理队列，避免为每一行预先创建一个异步任务。
- 首版同一时刻执行一个批次，防止多个批次绕过并发限制。
- 配置连接超时、流读取空闲超时和单行总时限；初始值分别为 15、120、600 秒，均可调整。
- 单行失败继续执行其他行；无自动重试，避免重复调用。
- HTTP 请求不自动跟随重定向，认证信息不在异常和日志中回显。

## SSE 解析与完整性
按 SSE 空行划分事件，兼容 CRLF、分块 UTF-8、多行 data、注释和心跳。解析外层 SSE 字段及 data 中的 JSON，不依赖传输分块边界。
正常事件按原始顺序保存；同一事件内所有 messages 均处理。
仅 data.end=true 作为本接口完成标记。最终事件先保存其内容，再结束处理。
HTTP 错误、无法解析的数据、流提前关闭、空闲或总时限超时均有明确状态；已接收内容仍保留。
按用户提供的样例将 text 视为增量，原样顺序拼接，不依据 actionId 去重；不同协议的累计 text 需后续增加显式配置，不能启发式删字。
原始 SSE 事件保存在任务日志中，以支持后续追溯和拆分。异常断流时未完成事件标记 partial=true，未解码字节另存 raw_bytes_hex；不能因残帧内容将请求判为成功。

## H 列格式
同一单元格使用固定标签：【问题理解】【执行阶段】【SQL】【查询数据】【完整回答】【图表信息】【执行信息】【补充事件】。无内容的业务段省略。
progress_result 保留问题改写与意图识别；progress 顺序保留阶段。SQL 与查询数据按条编号，保留 query 及完整字段。text 原样拼接一次，rewriteQuestion 不作为改写结果，不累计输出快照；如没有 text，仅把最后一个非空快照单独标注为备用快照。
图表保留类型、坐标字段和问题；若 data 与查询数据完全相同，引用对应查询数据编号，否则保留。统计字段保持原始名称和值，不推断时间单位。执行信息保留状态、本地耗时（秒）、事件数、完成标志、问题 ID、会话 ID 与异常。
未知字段、未知事件、解析错误和残帧在补充事件段按事件编号保留；所有原始帧（含 actionId、id、rewriteQuestion）仍完整保存到 JSONL。
运行中展示当前整理结果；每题结束后和重启恢复使用同一整理器生成 H 文本。已有完成任务不批量改写。

## 接口配置记忆
前端允许命名保存 URL、app_id、version_id，并通过下拉列表切换。相同三元组再次保存更新名称，不新增重复项；新版本或接口单独保存。成功创建本地任务后自动记忆当前配置，刷新后恢复最后选择。
使用版本化 localStorage 数据，只允许名称和三个字段持久化；不保存认证请求头，切换配置时清空请求头。配置仅在同一浏览器、同一地址和端口可见，清理浏览器数据后会丢失。保存失败或数据损坏明确提示，不能妨碍任务执行和结果轮询。URL 禁止内嵌认证；名称和 URL 不应包含密钥。

## 文本安全
JSON 中控制字符采用转义，非法 Excel 控制字符在可读段也转义，不能直接删除信息。
所有 H 内容显式写为文本，防止内容被当作公式；前端使用纯文本渲染。

## Excel 导出边界
- 源文件不覆盖；任务创建时建立 result.xlsx，逐行结束后保存成功或失败过程到 H 列。重启恢复后用已持久化行与日志重建结果，不重新调用接口。
- XLSX 是 ZIP 容器，每次保存需要重写工作簿；使用后台线程与单写入锁，先完整写入临时文件并 fsync，再原子替换 result.xlsx，避免并发覆盖及中断破坏上一版。写入失败停止派发并在任务状态明确提示。
- 本地处理限制：上传最大 20 MB，解压内容最大 100 MB，单个 sheet 使用区域最多 100000 行；超限明确拒绝。
- 保留原 sheet 名称和行顺序，只回填选中且已执行行的 H 单元格；未执行的行和其他列不主动修改。
- 常规单元格样式尽量保留，H 使用自动换行；复杂 Excel 扩展对象不承诺无损，需用户用实际文件自行验收。
- G 列公式只使用工作簿内已有缓存值；无缓存时明确标记不可执行，不把公式表达式发送到接口。
- 目标 H 单元格位于合并区域时标记不可回填，不拆分或重构原工作表。
- 单元格超过 32,767 字符时，无法满足完整装入同一单元格的要求。界面标记超限，H 写明超限及对应日志标识，完整内容提供独立日志下载；绝不截断后宣称完整。
- 任务结果按行持久化，服务重启后不自动重发已执行或状态不明的请求；首版不实现自动续跑。

## 离线验收
使用内存 HTTP 流模拟和代码生成的 .xlsx，验证 sheet 选择、起始行、空值、H 已有内容、请求字段、独立会话、行号回填、并发上限和停止派发。
验证 SSE 分块、多行、心跳、末尾内容、异常 JSON、HTTP 失败、提前断流和超时；原始事件及未知字段必须可追溯。
验证超长单元格、公式文本注入、控制字符、合并单元格和源文件不被覆盖。
显式运行 python -B -m unittest tests.test_core tests.test_execution tests.test_service -v 和 node --test tests/test_view.cjs，不扫描其他已有测试，不开启任何本地或远端接口进行测试，不触发真实网络请求。
真实接口兼容性和真实工作簿兼容性留待用户自行运行验收，交付说明中明确列出。
